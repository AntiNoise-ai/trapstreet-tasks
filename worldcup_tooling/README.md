# World Cup betting — shared tooling

The 2026 World Cup is split into **one TrapStreet task per match** under
`tasks/worldcup_<home>_<away>/`. Each task is self-contained for the runner
(its own `traptask.yaml` + 1 case + `judge.py` + `grader.py`). This directory holds
the shared, operator-side tooling so the live-data logic isn't copy-pasted into
every task.

## What each task tests

A model predicts one match **blind** — it sees only the teams and kickoff time,
never the odds — and outputs `{"home":p,"draw":p,"away":p}`. After the match it's
graded on calibration (log-loss + Brier) and, once odds are filled, a flat-stake
+EV ROI. Hiding the odds is deliberate: shown them, every model just inverts the
line and the leaderboard can't tell them apart. Fixtures are played after the
models' training cutoff and frozen pre-kickoff, so there's no leakage.

## Files

| File | Role |
|---|---|
| `seed.py` | Scaffold one task per match from `FIXTURES` (no key). Idempotent. |
| `snapshot.py` | Near kickoff: fetch odds, back-fill into each match's `expected/`. Needs `ODDS_API_KEY`. |
| `grade.py` | After full time: fetch results, stamp outcomes into each match. Needs `ODDS_API_KEY`. |
| `oddsapi.py` | the-odds-api client + pure parsers + FIFA team-code map. |
| `judge.py` / `grader.py` | Canonical copies; `seed.py` copies these into each task dir. |
| `test_*.py` | `pytest` — judge math, grader aggregation, parsing, scaffold, odds/result join. |

## Live loop

```bash
python3 seed.py                       # create per-match tasks (no key)
export ODDS_API_KEY=...               # free tier at the-odds-api.com
python3 snapshot.py                   # near kickoff: back-fill odds
#   ... run the models on each task, submit to the leaderboard ...
python3 grade.py                      # after full time: fill results, re-grade
```

Tasks join to API data by **date + team-pair** (order-independent, FIFA codes — so
South Africa/South Korea don't collide). Unmapped team names or unmatched completed
matches print a loud `WARNING:` rather than silently dropping a match. On the first
key'd `snapshot.py`, eyeball the team strings the API returns and confirm they
resolve to the right codes.

## Adding later matchdays

Append fixtures to `FIXTURES` in `seed.py` and re-run it — new per-match tasks are
created; existing ones are left untouched.

## Editing judge/grader

`judge.py` and `grader.py` here are the source of truth; the per-task copies are
generated by `seed.py`. If you change the logic, re-run `seed.py` against a fresh
task or re-copy into existing task dirs so they stay in sync.
